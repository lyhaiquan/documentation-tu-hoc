6 đơn vị · ~5 ngày

Biết Java rồi thì phần này đi nhanh, nhưng đừng bỏ qua: C khác Java ở những chỗ rất nhỏ mà gây lỗi rất lớn.

A1 Biên dịch và chạy chương trình đầu tiên 1 giờ›

Mục tiêu. Gõ được một chương trình, biên dịch, chạy, và hiểu mỗi bước làm gì.

Khái niệm

C là ngôn ngữ biên dịch trước, chạy sau. Không có máy ảo như Java. Mã nguồn .c đi qua bốn bước: tiền xử lý, biên dịch, hợp dịch, liên kết — ra một file thực thi chạy thẳng trên hệ điều hành.

main trả về int: 0 nghĩa là thành công, khác 0 là lỗi. Hệ điều hành đọc con số này.

/* xinchao.c */
#include <stdio.h>      // khai báo printf, không phải "nhập thư viện"

int main(void)
{
    printf("Xin chao\n");
    return 0;              // 0 = chạy tốt
}
gcc -Wall -g xinchao.c -o xinchao
./xinchao
echo $?                    # in ra mã thoát: 0
Bẫy. #include không giống import của Java. Nó chỉ dán nội dung file header vào — tức là dán các khai báo hàm. Mã thật của printf nằm trong thư viện C, được ghép vào ở bước liên kết. Đây là lý do có lỗi "undefined reference" dù đã #include đúng.
Bài tập
  1. In ra tên bạn và năm sinh trên hai dòng.
  2. Bỏ dòng #include <stdio.h> rồi biên dịch. Đọc kỹ cảnh báo gcc đưa ra và giải thích nó nói gì.
  3. Đổi return 0 thành return 3, chạy rồi kiểm tra echo $?.

C Primer Plus — Chương 1, 2

A2 Kiểu dữ liệu, biến, và sizeof 2 giờ›

Mục tiêu. Biết mỗi kiểu chiếm bao nhiêu byte và vì sao điều đó quan trọng.

Khái niệm

Khác Java, kích thước kiểu trong C không cố định theo chuẩn, chỉ có ràng buộc tối thiểu. Trên máy 64 bit thông thường: char 1 byte, short 2, int 4, long 8 trên Linux nhưng 4 trên Windows. Vì thế mọi code mạng đều dùng kiểu có kích thước cố định.

sizeof là toán tử, không phải hàm, và tính lúc biên dịch.

#include <stdio.h>

int main(void)
{
    char  c = 'A';
    int   i = 42;
    long  l = 42L;
    double d = 3.14;

    printf("char=%zu int=%zu long=%zu double=%zu\n",
           sizeof(c), sizeof(i), sizeof(l), sizeof(d));
    printf("c duoi dang so = %d\n", c);   // 65 — char LÀ số
    return 0;
}
Bẫy. char trong C là số nguyên 1 byte, không phải ký tự Unicode như Java. 'A' chính là 65. Và char có dấu hay không dấu là tùy trình biên dịch — khi đọc byte từ mạng luôn dùng unsigned char.
Bài tập
  1. In kích thước của tất cả kiểu cơ bản trên máy bạn, kể cả con trỏ sizeof(int *).
  2. Gán char c = 200; rồi in bằng %d. Giải thích kết quả.
  3. Cho int i = 3, j = 2; — in i / j. Vì sao ra 1? Sửa thế nào để ra 1.5?

C Primer Plus — Chương 3

A3 printf, scanf và chuỗi định dạng 2 giờ›

Mục tiêu. Nhập xuất thành thạo, và hiểu vì sao sai chuỗi định dạng lại nguy hiểm.

Khái niệm

printf nhận số tham số tùy ý. Nó không biết bạn truyền kiểu gì — nó tin vào chuỗi định dạng. Sai một ký tự là đọc nhầm vùng nhớ.

int   n = 42;
char  s[] = "chuoi";
double x = 2.5;

printf("%d\n", n);        // int
printf("%s\n", s);        // chuỗi
printf("%f  %.2f\n", x, x);
printf("%c\n", s[0]);     // một ký tự
printf("%p\n", (void *)s);// địa chỉ
printf("%5d|%-5d|\n", n, n);  // canh phải / canh trái

// scanf CẦN dấu & vì phải sửa biến của bạn — xem B4
int tuoi;
scanf("%d", &tuoi);
Bẫy. printf("%d", x) với x là double không báo lỗi lúc chạy, chỉ in ra số rác. Luôn bật gcc -Wall — nó bắt được lỗi này lúc biên dịch. Và không bao giờ viết printf(bien_chuoi); phải là printf("%s", bien_chuoi), nếu không là lỗ hổng format string.
Bài tập
  1. Viết chương trình hỏi tên và tuổi rồi in ra một câu chào.
  2. Cố tình dùng %d để in một double, biên dịch có và không có -Wall, so sánh.
  3. In một bảng 3 cột thẳng hàng bằng %-10s%5d%8.2f.

C Primer Plus — Chương 4

A4 Toán tử, ép kiểu, tràn số 2 giờ›

Mục tiêu. Đoán đúng kết quả của biểu thức trộn kiểu.

Khái niệm

C tự động nâng kiểu trong biểu thức: kiểu nhỏ nâng lên kiểu lớn. Nhưng phép chia hai số nguyên vẫn là chia nguyên, cắt phần thập phân, ngay cả khi gán vào double.

int a = 7, b = 2;
double d1 = a / b;          // 3.0  — chia nguyên TRƯỚC rồi mới gán
double d2 = (double)a / b;  // 3.5  — ép một vế là đủ

unsigned int u = 0;
u = u - 1;                  // 4294967295, KHÔNG phải -1

int big = 2147483647;
big = big + 1;              // tràn số có dấu = hành vi không xác định
Bẫy. So sánh giữa số có dấu và không dấu là nguồn lỗi kinh điển trong code mạng: if (len < sizeof(buf)) với len là int âm sẽ cho kết quả đúng một cách bất ngờ, vì sizeof trả về kiểu không dấu nên len bị chuyển thành số dương khổng lồ.
Bài tập
  1. Đoán rồi kiểm chứng: printf("%d\n", 5 / 2 * 2);
  2. Viết chương trình đổi độ C sang độ F, chú ý không để dính chia nguyên.
  3. Cho int n = -1; unsigned u = 1; — in kết quả của n < u. Giải thích.

C Primer Plus — Chương 5

A5 Rẽ nhánh và vòng lặp 2 giờ›

Mục tiêu. Viết được vòng lặp đọc dữ liệu tới khi hết — khuôn mẫu dùng suốt trong code mạng.

Khái niệm

C không có kiểu boolean theo nghĩa Java. Số 0 là sai, mọi giá trị khác là đúng. Vì thế con trỏ, số nguyên, ký tự đều đặt thẳng vào if được.

int c;
/* Khuôn mẫu đọc tới hết đầu vào.
   getchar() trả về int chứ không phải char, để chứa được EOF (-1). */
while ((c = getchar()) != EOF) {
    putchar(c);
}

/* Vòng lặp vô tận của server — bạn sẽ gặp lại ở F2 */
for (;;) {
    /* accept, xử lý, đóng */
    break;   // tạm thời
}
Bẫy. if (x = 5) — một dấu bằng — là phép gán, luôn đúng, và C không báo lỗi. Java bắt được vì if đòi boolean; C thì không. Bật -Wall để gcc cảnh báo.
Bài tập
  1. Đếm số ký tự, số dòng, số từ trong đầu vào — bài wc kinh điển.
  2. In bảng cửu chương bằng hai vòng lặp lồng nhau.
  3. Viết vòng lặp đọc số tới khi người dùng nhập 0 thì dừng, rồi in tổng.

C Primer Plus — Chương 6, 7, 8

A6 Hàm, nguyên mẫu, truyền theo giá trị 2 giờ›

Mục tiêu. Hiểu vì sao hàm C không thể đổi biến của người gọi — đây là lý do con trỏ tồn tại.

Khái niệm

C truyền tham số theo giá trị, luôn luôn. Hàm nhận một bản sao. Sửa bản sao thì bên ngoài không biết gì. Đây là nền tảng để hiểu đơn vị B4.

Nguyên mẫu hàm phải khai trước khi dùng, thường đặt trong file header.

#include <stdio.h>

int cong(int a, int b);        // nguyên mẫu
void thu_doi(int x);

int main(void)
{
    int n = 10;
    printf("%d\n", cong(2, 3));

    thu_doi(n);
    printf("n van la %d\n", n);   // vẫn 10!
    return 0;
}

int cong(int a, int b) { return a + b; }

void thu_doi(int x) { x = 999; }  // chỉ đổi bản sao
Bẫy. Quên nguyên mẫu thì trình biên dịch cũ tự đoán hàm trả về int, sinh lỗi rất khó tìm. Luôn khai nguyên mẫu, và luôn ghi void khi hàm không nhận tham số: int main(void) chứ không phải int main().
Bài tập
  1. Viết hàm tính giai thừa, gọi từ main.
  2. Viết hàm doi_cho(int a, int b) cố hoán đổi hai số. Chứng minh nó không hoạt động. Giữ lại bài này, đơn vị B4 sẽ sửa nó.
  3. Tách chương trình thành hai file: main.c và toan.c, biên dịch bằng gcc main.c toan.c -o ct.

B

Con trỏ — nút cổ chai

6 đơn vị · ~7 ngày

Đây là phần quyết định. Ai bỏ cuộc với C đều bỏ ở đây. Đi chậm, vẽ hình ra giấy, đừng vội sang phần sau.

B1 Bộ nhớ là gì, địa chỉ là gì 2 giờ›

Mục tiêu. Hình dung được bộ nhớ như một dãy ô đánh số, và biến nằm ở đâu trong dãy đó.

Khái niệm

Bộ nhớ là một dãy byte liên tiếp, mỗi byte có một địa chỉ là số nguyên. Khai báo int n; nghĩa là xin 4 byte liên tiếp và đặt tên n cho chúng. Toán tử & cho biết địa chỉ đó.

#include <stdio.h>

int main(void)
{
    int  a = 10;
    int  b = 20;
    char c = 'X';

    printf("a = %d, nam o dia chi %p\n", a, (void *)&a);
    printf("b = %d, nam o dia chi %p\n", b, (void *)&b);
    printf("c = %c, nam o dia chi %p\n", c, (void *)&c);
    printf("a chiem %zu byte\n", sizeof(a));
    return 0;
}

Chạy vài lần và để ý: địa chỉ đổi mỗi lần chạy (do hệ điều hành ngẫu nhiên hóa), nhưng khoảng cách giữa &a và &b thì ổn định.

Bẫy. In địa chỉ phải dùng %p và ép sang (void *). Dùng %d để in địa chỉ là sai kiểu, trên máy 64 bit sẽ in ra số cụt.
Bài tập
  1. Khai báo một mảng int arr[5], in địa chỉ từng phần tử. Khoảng cách giữa hai phần tử liền nhau là bao nhiêu? Vì sao?
  2. Làm lại với char arr[5] và so sánh.
  3. Vẽ ra giấy sơ đồ bộ nhớ của chương trình ví dụ trên.

C Primer Plus — Chương 10, phần đầu

B2 Con trỏ: khai báo, gán, lấy giá trị 3 giờ›

Mục tiêu. Đọc trôi chảy int *p = &a; và *p = 5; mà không phải nghĩ.

Khái niệm

Con trỏ là một biến chứa địa chỉ. Hai toán tử ngược nhau:

  • &x — lấy địa chỉ của x
  • *p — giá trị nằm tại địa chỉ p

Dấu * có hai nghĩa khác nhau tùy chỗ: lúc khai báo nó nói "đây là con trỏ", lúc dùng nó nói "lấy giá trị tại đó".

#include <stdio.h>

int main(void)
{
    int a = 10;
    int *p;          // p là con trỏ tới int (chưa trỏ đâu cả)

    p = &a;          // giờ p chứa địa chỉ của a

    printf("a  = %d\n", a);      // 10
    printf("*p = %d\n", *p);     // 10 — cùng một ô nhớ
    printf("p  = %p\n", (void *)p);
    printf("&a = %p\n", (void *)&a);   // hai dòng này giống nhau

    *p = 99;                     // ghi qua con trỏ
    printf("a gio la %d\n", a);  // 99 — a đã đổi!
    return 0;
}
Bẫy. Con trỏ chưa gán trỏ vào chỗ ngẫu nhiên. Viết int *p; *p = 5; là ghi vào một địa chỉ vô nghĩa — chương trình sập hoặc, tệ hơn, không sập mà phá dữ liệu khác. Luôn khởi tạo: int *p = NULL;
Bài tập
  1. Khai báo hai biến, hai con trỏ, cho chúng trỏ chéo nhau rồi in ra để kiểm chứng.
  2. Viết int **pp = &p; và in **pp. Vẽ sơ đồ ba ô nhớ nối nhau.
  3. Thử int *p = NULL; printf("%d", *p); — quan sát chương trình sập, và nhớ thông báo lỗi đó.

C Primer Plus — Chương 10

B3 Con trỏ và mảng, số học con trỏ 3 giờ›

Mục tiêu. Hiểu vì sao arr[i] và *(arr + i) là một.

Khái niệm

Tên mảng, khi dùng trong biểu thức, tự chuyển thành địa chỉ phần tử đầu. Cộng 1 vào con trỏ không cộng 1 byte mà cộng một phần tử — trình biên dịch tự nhân với sizeof kiểu.

#include <stdio.h>

int main(void)
{
    int arr[5] = {10, 20, 30, 40, 50};
    int *p = arr;            // không cần &, tên mảng đã là địa chỉ

    printf("%d %d\n", arr[2], *(arr + 2));  // 30 30 — như nhau
    printf("%d %d\n", p[2],   *(p + 2));    // 30 30

    // duyệt bằng con trỏ
    for (int i = 0; i < 5; i++)
        printf("%d ", *(p + i));
    printf("\n");

    printf("sizeof(arr) = %zu\n", sizeof(arr));  // 20 — cả mảng
    printf("sizeof(p)   = %zu\n", sizeof(p));    // 8  — chỉ con trỏ
    return 0;
}
Bẫy. Khi truyền mảng vào hàm, nó suy biến thành con trỏ và mất thông tin kích thước. Bên trong hàm, sizeof(arr) trả về kích thước con trỏ chứ không phải mảng. Vì thế mọi hàm C nhận mảng đều phải kèm thêm tham số độ dài — chính là lý do read(fd, buf, len) có tham số len.
Bài tập
  1. Viết hàm int tong(int *a, int n) tính tổng mảng.
  2. In arr, &arr[0], p, p + 1 — giải thích khoảng cách giữa p và p + 1.
  3. Viết hàm đảo ngược mảng tại chỗ, dùng hai con trỏ chạy từ hai đầu vào giữa.

C Primer Plus — Chương 10

B4 Con trỏ làm tham số — sửa biến của người gọi 2 giờ›

Mục tiêu. Sửa được bài hoán đổi ở A6, và hiểu tham số kiểu "giá trị-kết quả" mà API socket dùng.

Khái niệm

Hàm không đổi được biến của người gọi, nhưng đổi được thứ mà con trỏ trỏ tới. Truyền địa chỉ thay vì giá trị.

#include <stdio.h>

void doi_cho(int *a, int *b)
{
    int tam = *a;
    *a = *b;
    *b = tam;
}

int main(void)
{
    int x = 1, y = 2;
    doi_cho(&x, &y);            // truyền ĐỊA CHỈ
    printf("x=%d y=%d\n", x, y); // x=2 y=1
    return 0;
}

Đây chính là lý do scanf("%d", &tuoi) phải có dấu &: scanf cần ghi vào biến của bạn.

Đây là chỗ nối sang lập trình mạng. Hàm accept() dùng kiểu tham số "giá trị-kết quả": 
socklen_t len = sizeof(cliaddr);
connfd = accept(fd, (struct sockaddr *)&cliaddr, &len);
len vừa là đầu vào (bộ đệm to bao nhiêu) vừa là đầu ra (thực tế điền bao nhiêu). Truyền &len để hàm ghi ngược lại được. Java không có khái niệm này.
Bài tập
  1. Sửa bài doi_cho ở A6 cho chạy đúng.
  2. Viết hàm void min_max(int *a, int n, int *min, int *max) trả về hai giá trị qua tham số.
  3. Viết hàm int chia(int a, int b, int *ket_qua) trả về 0 nếu ổn, -1 nếu chia cho 0 — đúng phong cách trả lỗi của C.

C Primer Plus — Chương 9, 10

B5 Chuỗi C và tràn bộ đệm 3 giờ›

Mục tiêu. Xử lý chuỗi an toàn — kỹ năng sống còn khi nhận dữ liệu từ mạng.

Khái niệm

C không có kiểu chuỗi. Chuỗi chỉ là mảng char kết thúc bằng byte 0 ('\0'). Mọi hàm chuỗi đều dựa vào byte kết thúc đó. Thiếu nó là hàm chạy quá vùng nhớ.

#include <stdio.h>
#include <string.h>

int main(void)
{
    char s1[] = "abc";       // chiếm 4 byte: a b c \0
    char s2[10];

    printf("do dai = %zu, kich thuoc = %zu\n", strlen(s1), sizeof(s1));

    strcpy(s2, s1);          // nguy hiểm nếu s1 dài hơn s2
    strncpy(s2, s1, sizeof(s2) - 1);
    s2[sizeof(s2) - 1] = '\0';   // strncpy KHÔNG tự thêm '\0'

    printf("%s\n", s2);
    return 0;
}
Bẫy chết người. char buf[8]; strcpy(buf, "chuoi rat dai"); ghi đè ra ngoài mảng, phá stack. Đây chính là lỗ hổng tràn bộ đệm — và là lý do code mạng luôn phải kiểm độ dài trước khi sao chép. Không bao giờ dùng gets(); nó đã bị loại khỏi chuẩn C11.
Bài tập
  1. Tự viết lại strlen và strcpy bằng con trỏ.
  2. Viết hàm đếm số lần xuất hiện của một ký tự trong chuỗi.
  3. Cố tình tràn một mảng char buf[4] rồi biên dịch với gcc -fsanitize=address, đọc báo cáo lỗi.

C Primer Plus — Chương 11

B6 Con trỏ tới con trỏ, argv 2 giờ›

Mục tiêu. Đọc được char **argv và mảng con trỏ.

Khái niệm

char **argv là con trỏ tới con trỏ tới char: một mảng các chuỗi. Đây là cách chương trình C nhận tham số dòng lệnh.

#include <stdio.h>

int main(int argc, char **argv)
{
    printf("So tham so: %d\n", argc);
    for (int i = 0; i < argc; i++)
        printf("argv[%d] = %s\n", i, argv[i]);
    return 0;
}
/* ./ct alpha beta
   argv[0] = ./ct
   argv[1] = alpha
   argv[2] = beta   */
Bẫy. argv[0] là tên chương trình, không phải tham số đầu tiên. Và mọi phần tử đều là chuỗi — muốn số phải đổi bằng atoi() hoặc strtol(). Mọi ví dụ trong UNP đều nhận địa chỉ IP qua argv[1].
Bài tập

  2. Khai báo char *ten[] = {"an", "binh", "chi"}; rồi duyệt in ra. Vẽ sơ đồ bộ nhớ.

C1 Ba vùng nhớ: stack, heap, tĩnh 2 giờ›

Mục tiêu. Biết biến của mình nằm vùng nào và sống được bao lâu.

Khái niệm
  • Stack — biến cục bộ. Tự sinh khi vào hàm, tự mất khi ra. Nhanh, nhỏ.
  • Heap — vùng bạn xin bằng malloc. Sống tới khi bạn free. To, chậm hơn.

#include <stdio.h>

int toan_cuc = 1;               // vùng tĩnh

{

{

C2 malloc, free, và bốn lỗi bộ nhớ 3 giờ›

Mục tiêu. Cấp phát và giải phóng đúng, nhận diện được bốn loại lỗi bộ nhớ.

Khái niệm

malloc(n) xin n byte, trả về void * hoặc NULL nếu thất bại. free(p) trả lại. Mỗi malloc phải có đúng một free.

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int n = 5;
    int *a = malloc(n * sizeof(int));   // KHÔNG cần ép kiểu trong C
    if (a == NULL) {                    // LUÔN kiểm tra
        fprintf(stderr, "het bo nho\n");
        return 1;
    }

    for (int i = 0; i < n; i++) a[i] = i * i;
    for (int i = 0; i < n; i++) printf("%d ", a[i]);
    printf("\n");

    free(a);
    a = NULL;      // gán NULL sau khi free, tránh dùng nhầm
    return 0;
}
Bốn lỗi phải thuộc tên
  • Rò rỉ bộ nhớ — xin mà không trả. Server chạy vài ngày rồi hết RAM.
  • Dùng sau khi giải phóng — free(p) rồi vẫn đọc *p.
  • Giải phóng hai lần — free cùng con trỏ hai lượt.
  • Ghi quá vùng — xin 5 phần tử mà ghi phần tử thứ 6.
Bẫy. malloc không xóa vùng nhớ; nội dung là rác của chương trình trước. Cần vùng sạch thì dùng calloc(n, size).
Bài tập
  1. Viết hàm đọc n số từ bàn phím vào mảng cấp phát động rồi in ngược lại.
  2. Cố tình tạo một chỗ rò rỉ, biên dịch với gcc -fsanitize=address và đọc báo cáo.
  3. Viết hàm char *noi_chuoi(const char *a, const char *b) nối hai chuỗi vào vùng nhớ mới. Ai chịu trách nhiệm free?

C3 Lớp lưu trữ, phạm vi, liên kết 2 giờ›

Mục tiêu. Chia chương trình thành nhiều file mà không đụng tên nhau.

Khái niệm
  • static ở cấp file — biến hoặc hàm chỉ dùng trong file đó, giống private.
  • static trong hàm — biến sống suốt chương trình nhưng chỉ hàm đó thấy.
  • extern — báo rằng biến này định nghĩa ở file khác.
  • const — không được sửa. Trong API socket rất hay gặp: const struct sockaddr * nghĩa là "hàm này chỉ đọc, không sửa".
/* toan.c */

int tang(void) { return ++bo_dem; }

/* toan.h */

#define TOAN_H
int tang(void);
#endif
Bẫy. Đặt định nghĩa biến trong file .h rồi #include vào nhiều file .c sẽ gây lỗi "multiple definition" lúc liên kết. Header chỉ chứa khai báo, còn định nghĩa nằm trong .c.
Bài tập

D1 struct: khai báo, truy cập, gán 2 giờ›

Mục tiêu. Gom nhiều trường thành một kiểu, như struct sockaddr_in.

Khái niệm

struct gộp các biến khác kiểu vào một khối liên tiếp trong bộ nhớ. Truy cập trường bằng dấu chấm.

#include <stdio.h>
#include <string.h>

struct sinh_vien {
    char ten[32];
    int  tuoi;
    double diem;
};

int main(void)
{
    struct sinh_vien a;
    strcpy(a.ten, "An");
    a.tuoi = 20;
    a.diem = 8.5;

    struct sinh_vien b = a;      // gán struct = SAO CHÉP toàn bộ
    b.tuoi = 21;

    printf("%s %d %.1f\n", a.ten, a.tuoi, a.diem);   // An 20 8.5
    printf("%s %d %.1f\n", b.ten, b.tuoi, b.diem);   // An 21 8.5
    printf("kich thuoc = %zu\n", sizeof(struct sinh_vien));
    return 0;
}
Bẫy. sizeof của struct thường lớn hơn tổng các trường, do trình biên dịch chèn byte đệm để căn chỉnh địa chỉ. Đây là lý do không được gửi thẳng struct qua mạng — hai máy có thể đệm khác nhau.

D3 typedef, union, enum 2 giờ›

Mục tiêu. Đọc được socklen_t, struct sockaddr_storage và các hằng AF_INET.

Khái niệm
  • typedef — đặt tên khác cho một kiểu. socklen_t thực chất chỉ là unsigned int được đặt tên lại.
  • union — nhiều trường dùng chung một vùng nhớ, chỉ một trường có nghĩa tại một thời điểm. Kích thước bằng trường lớn nhất.
  • enum — tập hằng số nguyên có tên.
#include <stdio.h>

typedef unsigned int uint;

union so {
    int    i;
    float  f;
    char   b[4];
};

enum trang_thai { CHO, DANG_CHAY, XONG };

int main(void)
{

    s.i = 65;
    printf("i=%d, byte dau=%d\n", s.i, s.b[0]);  // thấy được từng byte
    printf("sizeof(union) = %zu\n", sizeof(s));  // 4, không phải 12

D4 Cấu trúc tự tham chiếu — danh sách liên kết 3 giờ›

Mục tiêu. Ghép con trỏ và struct lại — bài kiểm tra tổng hợp của giai đoạn B, C, D.

Khái niệm

Một struct chứa con trỏ tới chính kiểu của nó. Đây là nền của mọi cấu trúc dữ liệu động, và server thật dùng nó để giữ danh sách client đang kết nối.

#include <stdio.h>
#include <stdlib.h>

struct nut {
    int          gia_tri;
    struct nut  *tiep;      // trỏ tới chính kiểu này
};

int main(void)
{
    struct nut *dau = NULL;

    /* thêm 3 nút vào đầu danh sách */
    for (int i = 1; i <= 3; i++) {
        struct nut *moi = malloc(sizeof(struct nut));
        if (!moi) return 1;
        moi->gia_tri = i;
        moi->tiep    = dau;
        dau          = moi;
    }

    for (struct nut *p = dau; p != NULL; p = p->tiep)
        printf("%d ", p->gia_tri);
    printf("\n");

    /* giải phóng — phải giữ con trỏ tiếp trước khi free */
    while (dau) {
        struct nut *tam = dau->tiep;
        free(dau);
        dau = tam;
    }
    return 0;
}
Bẫy. free(dau); dau = dau->tiep; là lỗi dùng sau khi giải phóng — đọc trường của vùng nhớ vừa trả lại. Phải lưu tiep vào biến tạm trước khi free.
Bài tập
  1. Thêm hàm them_cuoi chèn vào cuối danh sách.
  2. Viết hàm xoa(struct nut **dau, int gia_tri) — vì sao cần con trỏ tới con trỏ?
  3. Viết hàm đảo ngược danh sách bằng ba con trỏ chạy.

E1 Thao tác bit và mặt nạ cờ 2 giờ›

Mục tiêu. Đọc được flags | O_NONBLOCK và flags & O_NONBLOCK.

Khái niệm

Sáu toán tử: & và, | hoặc, ^ xor, ~ đảo, << dịch trái, >> dịch phải. Hệ thống Unix gói nhiều tùy chọn nhị phân vào một số nguyên gọi là cờ.

#include <stdio.h>

#define DOC   (1 << 0)   // 0001
#define GHI   (1 << 1)   // 0010
#define CHAY  (1 << 2)   // 0100

int main(void)
{
    int quyen = 0;

    quyen |= DOC;              // bật cờ
    quyen |= GHI;

    if (quyen & DOC)  printf("co quyen doc\n");     // kiểm tra
    if (!(quyen & CHAY)) printf("khong duoc chay\n");

    quyen &= ~GHI;             // tắt cờ
    printf("quyen = %d\n", quyen);   // 1
    return 0;
}
Bẫy. Đừng nhầm & với &&, | với ||. Cặp một ký tự làm việc trên từng bit, cặp hai ký tự làm việc trên đúng/sai. Viết nhầm thì chương trình vẫn biên dịch và cho kết quả sai âm thầm.
Bài tập
  1. Viết hàm đếm số bit 1 trong một unsigned int.
  2. Viết hàm in một số dưới dạng nhị phân 32 bit.
  3. Dùng dịch bit tách bốn byte của một uint32_t ra riêng.

E2 Kiểu kích thước cố định và thứ tự byte 3 giờ›

Mục tiêu. Hiểu vì sao code mạng luôn gọi htons().

Khái niệm

Vì int không cố định kích thước, giao thức mạng dùng kiểu chính xác: uint8_t, uint16_t, uint32_t trong <stdint.h>. Ngoài ra còn size_t (kích thước, không dấu) và ssize_t (kích thước có dấu, để trả về -1 khi lỗi).

Endianness — thứ tự các byte của một số nhiều byte. x86 dùng little-endian (byte thấp trước), còn mạng quy ước big-endian. Nên mọi số nhiều byte gửi đi đều phải đổi.

#include <stdio.h>
#include <stdint.h>

int main(void)
{
    uint32_t x = 0x01020304;
    unsigned char *b = (unsigned char *)&x;

    printf("byte: %02x %02x %02x %02x\n", b[0], b[1], b[2], b[3]);
    // x86 in ra: 04 03 02 01  -> little-endian
    // mạng cần:  01 02 03 04  -> big-endian

    if (b[0] == 0x04) printf("may nay little-endian\n");
    else              printf("may nay big-endian\n");
    return 0;
}

Trong code mạng: htons = host to network short (16 bit), htonl = host to network long (32 bit), và hai hàm ngược lại ntohs, ntohl.

Bẫy. Quên htons(5000) thì cổng gửi đi thành 34835 — server nghe ở cổng khác hẳn cổng bạn nghĩ, và không có thông báo lỗi nào cả.
Bài tập
  1. Chạy ví dụ trên, xác định máy bạn thuộc loại nào.
  2. Tự viết hàm uint16_t doi_16(uint16_t x) đảo hai byte, so kết quả với htons.
  3. In htons(5000) dưới dạng thập phân. Con số đó nói lên điều gì?

E3 Con trỏ hàm 2 giờ›

Mục tiêu. Đọc được signal(SIGINT, xu_ly) và tham số so sánh của qsort.

Khái niệm

Tên hàm cũng là một địa chỉ. Con trỏ hàm cho phép truyền hành vi vào hàm khác — chính là callback. Trong lập trình mạng, bộ xử lý tín hiệu là con trỏ hàm.

#include <stdio.h>
#include <stdlib.h>

int tang_dan(const void *a, const void *b)
{
    int x = *(const int *)a;
    int y = *(const int *)b;
    return (x > y) - (x < y);
}

int main(void)
{
    int arr[5] = {5, 2, 9, 1, 7};
    qsort(arr, 5, sizeof(int), tang_dan);   // truyền tên hàm

    for (int i = 0; i < 5; i++) printf("%d ", arr[i]);
    printf("\n");

    int (*ham)(const void *, const void *) = tang_dan;  // biến con trỏ hàm
    printf("%d\n", ham(&arr[0], &arr[1]));
    return 0;
}
Bẫy. Cú pháp khai báo rất khó đọc. int (*p)(int) là con trỏ tới hàm nhận int trả int; còn int *p(int) là hàm trả về con trỏ int. Dấu ngoặc quyết định tất cả. Dùng typedef cho dễ đọc.
Bài tập
  1. Sửa hàm so sánh để sắp giảm dần.
  2. Viết hàm ap_dung(int *a, int n, int (*f)(int)) áp dụng f lên từng phần tử.
  3. Dùng typedef int (*SoSanh)(const void *, const void *); viết lại cho gọn.

Mục tiêu. Xử lý lỗi đúng phong cách Unix — vì socket dùng y hệt cách này.

Khái niệm

Có hai tầng: FILE * với fopen/fread (thư viện chuẩn C, có bộ đệm) và mô tả file là số nguyên với open/read/write (lời gọi hệ thống). Socket là mô tả file, nên tầng thứ hai mới là thứ bạn cần.

Quy ước Unix: hàm trả về -1 khi lỗi và đặt biến toàn cục errno cho biết lỗi gì.

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <errno.h>

int main(void)
{
    FILE *f = fopen("khong_co_file_nay.txt", "r");
    if (f == NULL) {
        /* ba cách in lỗi, chọn một */
        perror("fopen");
        fprintf(stderr, "errno = %d: %s\n", errno, strerror(errno));
        return 1;
    }

    char dong[256];
    while (fgets(dong, sizeof(dong), f) != NULL)
        fputs(dong, stdout);

    fclose(f);
    return 0;
}

Bản dùng mô tả file, gần với socket hơn:

#include <fcntl.h>
#include <unistd.h>

int fd = open("a.txt", O_RDONLY);
if (fd == -1) { perror("open"); return 1; }

char buf[1024];
ssize_t n;
while ((n = read(fd, buf, sizeof(buf))) > 0)
    write(STDOUT_FILENO, buf, n);   // ghi đúng n byte, không phải sizeof

if (n == -1) perror("read");
close(fd);
Bẫy quan trọng nhất cho lập trình mạng. read() có thể trả về ít hơn số byte bạn xin, dù chưa hết dữ liệu. Trên socket điều này xảy ra thường xuyên. Luôn dùng vòng lặp và luôn dùng giá trị n trả về, không giả định đã đọc đủ.
Bài tập
  1. Viết chương trình sao chép file, dùng open/read/write.
  2. Mở file không tồn tại rồi in errno và strerror(errno).
  3. Viết hàm ssize_t doc_du(int fd, void *buf, size_t n) lặp cho tới khi đọc đủ n byte — đây chính là hàm readn trong UNP.

F2 Giải mã code socket và viết server đầu tiên 4 giờ›

Mục tiêu. Đọc trôi dòng bind() và viết được một server echo bằng C.

Giải mã dòng kiểm tra
if (bind(sockfd, (struct sockaddr *)&servaddr, sizeof(servaddr)) < 0)
    perror("bind");
  • sockfd — mô tả file, một số nguyên → E5
  • &servaddr — lấy địa chỉ của struct → B1, D2
  • (struct sockaddr *) — ép kiểu con trỏ → B2, D1
  • sizeof(servaddr) — kích thước struct → A2, D1
  • < 0 — quy ước trả lỗi của Unix → E5
  • perror — in errno → E5

Sáu đơn vị bạn đã học hội tụ vào một dòng. Nếu chỗ nào còn mơ hồ, quay lại đúng đơn vị đó.

Khung server echo
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <arpa/inet.h>

#define CONG 5000

int main(void)
{
    int listenfd = socket(AF_INET, SOCK_STREAM, 0);
    if (listenfd < 0) { perror("socket"); return 1; }

    struct sockaddr_in servaddr;
    memset(&servaddr, 0, sizeof(servaddr));      // xóa sạch trước khi điền
    servaddr.sin_family      = AF_INET;
    servaddr.sin_addr.s_addr = htonl(INADDR_ANY);
    servaddr.sin_port        = htons(CONG);      // E2: đổi thứ tự byte

    if (bind(listenfd, (struct sockaddr *)&servaddr, sizeof(servaddr)) < 0) {
        perror("bind"); return 1;
    }
    if (listen(listenfd, 10) < 0) { perror("listen"); return 1; }

    printf("Dang nghe o cong %d...\n", CONG);

    for (;;) {
        struct sockaddr_in cli;
        socklen_t len = sizeof(cli);             // B4: giá trị-kết quả
        int connfd = accept(listenfd, (struct sockaddr *)&cli, &len);
        if (connfd < 0) { perror("accept"); continue; }

        char buf[1024];
        ssize_t n;
        while ((n = read(connfd, buf, sizeof(buf))) > 0)
            write(connfd, buf, n);               // E5: ghi đúng n byte

        close(connfd);
    }
    return 0;
}
Lưu ý. Chương trình này cần Linux — trên WSL2 biên dịch gcc -Wall server.c -o server rồi thử bằng telnet localhost 5000 hoặc nc localhost 5000. Trên Windows thuần thì <arpa/inet.h> không tồn tại.
Bài tập
  1. Biên dịch và chạy server trên, kết nối bằng nc.
  2. Thêm in ra địa chỉ IP client bằng inet_ntoa(cli.sin_addr).
  3. Bỏ htons đi, chạy lại, dùng ss -tlnp xem server thật sự nghe ở cổng nào. Đây là bài học đắt giá nhất của E2.
